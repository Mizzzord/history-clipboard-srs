## Как проверено

Настройки GitHub подтверждают публичный доступ и включённые Wiki/Issues. Репозиторий, Wiki и страницы всех четырёх задач открываются HTTP-запросами без авторизации. Проверены наличие User Story, критериев, назначенных меток, ссылок из ТЗ на Issues и существующих якорей разделов Wiki в обратных ссылках. Markdown-копия ТЗ совпадает с содержимым Wiki.

Этот чек-лист подтверждает оформление учебного задания. Результаты функциональных проверок приложения и оставшееся покрытие версий ОС приведены в [отчёте о приёмке](docs/ACCEPTANCE.md). Критерии в Issues остаются доступными для отдельной приёмки; оформление репозитория не означает их автоматическое прохождение на всех заявленных ОС.

## Обновление материалов

1. При изменении требований обновляйте `Техническое-задание.md` и одноимённую страницу Wiki одинаковым текстом.
2. При изменении задач согласуйте файлы `issues/*.md` с описаниями GitHub Issues; сохраняйте User Story, критерии, метки и обратные ссылки.
3. При добавлении или перенумерации задач обновляйте таблицу ссылок в ТЗ и проверяйте переходы в обе стороны.

Для сдачи преподавателю достаточно передать ссылку на публичный репозиторий. Отправка сообщения преподавателю в эту работу не входит.
