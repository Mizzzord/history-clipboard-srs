# Размещение на GitHub

Архив содержит материалы практического задания по требованиям. Исполняемого кода приложения в нём нет.

## 1. Репозиторий

1. На GitHub создайте **публичный** репозиторий `history-clipboard-srs` в аккаунте `Mizzzord`.
2. Описание: `Техническое задание для приложения History Clipboard — менеджера истории текстового буфера обмена`.
3. Включите Issues и Wiki. Загрузите `README.md` из архива в корень репозитория (если GitHub уже создал README, замените его текст содержимым этого файла).
4. При желании загрузите `Техническое-задание.md` в репозиторий как резервную копию документа. Для выполнения задания отдельно создайте настоящую страницу **Wiki**.

## 2. Wiki

1. Откройте вкладку Wiki → Create the first page.
2. Название страницы: `Техническое задание`.
3. Вставьте в редактор содержимое файла `Техническое-задание.md` и сохраните страницу.

## 3. Issues

Создайте четыре Issues в приведённом порядке, копируя текст из файлов ниже. Первую строку `# ...` используйте как название задачи, остальной текст — как её описание. Проставьте стандартную метку `enhancement`.

| Очередь | Файл | Ожидаемый номер в новом пустом репозитории |
| --- | --- | --- |
| 1 | `issues/01-сбор.md` | #1 |
| 2 | `issues/02-просмотр.md` | #2 |
| 3 | `issues/03-управление.md` | #3 |
| 4 | `issues/04-хранение.md` | #4 |

Если GitHub выдал другие номера, исправьте ссылки в разделе 6 страницы Wiki. Ссылки в самих Issues ведут на разделы ТЗ и от номеров задач не зависят.

## 4. Проверка

- Репозиторий открывается без входа в аккаунт, его название и README корректны.
- Во вкладке Wiki есть сохранённая страница «Техническое задание» с пятью основными разделами требований и таблицей ссылок на Issues.
- Открыты четыре Issues: в каждой есть User Story, чек-лист приёмки, метка `enhancement` и ссылка на Wiki.
- Все четыре ссылки из Wiki открывают нужные Issues; ссылки в Issues открывают Wiki.

Передайте преподавателю ссылку на репозиторий. В исходном снимке инструкции указан адрес получателя, но отправку письма архив не выполняет.
