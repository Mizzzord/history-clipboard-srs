# План разработки History Clipboard

Цель сессии: реализовать MVP из ТЗ, проверить поведение и получить самостоятельные исполняемые сборки Windows x64 (.exe), macOS Apple Silicon и macOS Intel (.app).

## Этапы

- [x] Проверить среду и выбрать стек, позволяющий собрать обе платформы локально.
- [x] Реализовать хранилище, правила истории и автоматические проверки.
- [x] Реализовать платформенный сбор буфера, паузу и исключение собственных копирований.
- [x] Реализовать русский интерфейс, поиск, просмотр, удаление и предупреждение первого запуска.
- [x] Проверить интеграцию с настоящим буфером macOS и пройти интерфейс.
- [x] Собрать Windows exe и macOS app, проверить форматы и запуск доступных сборок.
- [x] Проверить итоговые изменения и подготовить инструкции и отчёт о приёмке.

## Принятые правила MVP

- Буфер, существовавший до запуска или скопированный на паузе, не добавляется задним числом.
- Пустая строка игнорируется; пробелы, табуляция и переводы строк сохраняются точно.
- Дедупликация относится к последовательным наблюдаемым текстовым копированиям, а не ко всей базе. Удаление истории не сбрасывает состояние наблюдения.
- Время записи — локальное время обнаружения с часовым поясом; порядок определяется идентификатором добавления.
- Сбор начинается после прочтения предупреждения первого запуска. Закрытие окна завершает приложение.
- Повреждённое хранилище не изменяется автоматически. Новая история создаётся явным действием с сохранением исходных файлов.
- Ошибки записи не выдаются за успешное сохранение или удаление.
- Лимиты: 500 записей и 1 048 576 байт UTF-8 на запись. 100 МБ из исходного ТЗ недостаточно для максимальной истории; требование уточняется в инструкции продукта без изменения исходного ТЗ.
- Периодическое чтение текущего буфера не обещает восстановить промежуточные значения, уже заменённые другим копированием.

## Проверка и ограничения

Исполняемый артефакт и проверенный запуск — отдельные результаты. Windows и Intel macOS нельзя считать проверенными по одному запуску на Apple Silicon macOS. Публикация и push разрешены отдельным поручением пользователя; сборки поставляются через GitHub Releases. Merge не выполняется.

## Ход работы

30.09.2026: исходный репозиторий содержит только семь документов; рабочее дерево до разработки чистое. Хост — macOS arm64, доступны clang, codesign и hdiutil; Python 3.13, .NET SDK и Windows/Wine отсутствуют. Предварительный Python/Qt стек из разбора пересматривается для получения настоящего Windows exe на этом хосте.

Выбран C#/.NET 8.0.425 + Avalonia 11.3.22 + Microsoft.Data.Sqlite 8.0.31. SDK установлен только в игнорируемую `.tools` проекта. Исходники изменяются в локальной ветке `codex/desktop-mvp`; разработка ведётся последовательно с осмысленными коммитами.

Первичные 18 тестов логики/SQLite прошли. Native-проверка macOS подтвердила точное сохранение Unicode/CRLF/табуляции, повторы, пустой буфер, граничный размер и паузу. Задержка появления в базе в этом прогоне: 0.07–0.27 с. Проверка первого запуска и состояния поиска выполнена через настоящий интерфейс.

Обнаруженные и исправляемые проблемы: Cmd+Enter перехватывался списком — обработчик перенесён в туннель событий; отображение 1 МиБ с переносом строк перегружало TextBox — добавлен просмотр по частям до 8192 кодовых единиц с сохранением Unicode-пар и CRLF, копирование всегда полного текста; чтение отделено от записи, SQLite использует WAL. Добавлены регрессионные проверки клавиатуры, диалога, частей текста и параллельного чтения/записи. Финальный общий набор: 23 теста. Дополнительно по одному native-тесту Windows/macOS, включаемому только в одноразовой CI-среде.

Подпись .app требует подписывать все файлы в Contents/MacOS, включая managed DLL и JSON, затем пакет; исправленная упаковка проходит codesign --verify --deep --strict. Mac Intel не запускается на этом хосте: Rosetta отсутствует (arch -x86_64 сообщает Bad CPU type). Windows среды также нет. Проверки этих ОС явно отделяются от успешной кросс-сборки.

Финальная локальная проверка упакованного продукта: семь native-сценариев прошли; задержка 0,062–0,216 с. Запись 1 МиБ просматривается по частям без зависания, повторное копирование возвращает весь текст и не увеличивает историю. Повреждённая QA-база проверена через интерфейс: не заменяется автоматически, после подтверждения сохранена точная резервная копия и создана пустая история на паузе.

После разрешения пользователя подключён GitHub Actions для Windows x64, macOS arm64 и Intel x64. Windows native-адаптер и self-test реального exe прошли; CI выявил ошибку кодировки русского манифеста в упаковочном Python-скрипте — запись исправлена на явный UTF-8. Новые коммиты разделяют реализацию, упаковку, исправление и платформенные проверки.

Передача: README со снимком реального интерфейса на вымышленных данных, руководством, ссылками загрузки и границами проверки. Полный статус и остаточные ограничения зафиксированы в docs/ACCEPTANCE.md.

Финальная дополнительная проверка поставки выявила остановку наблюдения в одном первом фоновом прогоне; возврат окна и повторный запуск наблюдения восстановили сбор. Для непрерывного сбора macOS объявляет активность NSProcessInfo с разрешённым обычным сном, снимает её на паузе/закрытии и удерживает объект NSPasteboard на время использования. После исправления первый запуск и повторный прогон после более минуты со свёрнутым окном прошли; максимальная задержка фонового прогона 0,328 с. Cmd+Enter повторно проверен на полной записи 1 МиБ. Исходный буфер восстановлен, QA-приложение закрыто.
