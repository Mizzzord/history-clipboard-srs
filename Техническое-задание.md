# Техническое задание: History Clipboard

## 1. Наименование и область применения

**Наименование:** History Clipboard — менеджер истории текстового буфера обмена.

**Назначение:** настольное приложение для возвращения ранее скопированных фрагментов текста. Пользователь может просмотреть историю, найти запись, повторно поместить её в системный буфер обмена и удалить ненужные данные.

**Пользователи:** люди, которые часто работают с текстом в нескольких приложениях. MVP предназначен для одного пользователя на одном устройстве.

**Границы MVP:** только текст, скопированный после запуска приложения при включённом сборе. Изображения, файлы, форматированный текст, облачная синхронизация и обмен историей между учётными записями не входят в первую версию.

## 2. Функциональные требования

### 2.1. Сбор истории

| ID | Требование | Проверка |
| --- | --- | --- |
| FR-01 | При включённом сборе приложение обнаруживает изменение текстового содержимого системного буфера и добавляет новую запись в историю не позднее чем через 2 секунды после копирования. | Скопировать текст из другого приложения и проверить запись и время появления. |
| FR-02 | Пустой текст не сохраняется. Два последовательных копирования идентичного текста дают одну запись; повтор текста после другой записи создаёт новую запись. | Повторить три сценария копирования. |
| FR-03 | Запись хранит текст и локальную дату/время добавления. Размер одной записи ограничен 1 МиБ в UTF-8; при превышении приложение сообщает, что запись не сохранена. | Проверить отображение даты и граничные размеры. |

### 2.2. Просмотр и управление

| ID | Требование | Проверка |
| --- | --- | --- |
| FR-04 | История отображается от новой записи к старой. Длинный текст показывается сокращённо, а полный текст доступен при выборе записи. | Добавить несколько коротких и длинных записей. |
| FR-05 | Поиск без учёта регистра фильтрует записи по подстроке текста; очистка запроса возвращает весь список. | Проверить совпадение в середине записи и разные регистры. |
| FR-06 | Действие «Скопировать» помещает полный текст выбранной записи в системный буфер. Это действие само по себе не создаёт новую запись истории. | Вставить результат в другое приложение и проверить количество записей. |
| FR-07 | Можно удалить одну запись или всю историю; перед удалением всей истории запрашивается подтверждение. После удаления записи недоступны в интерфейсе и после перезапуска. | Выполнить оба удаления, отмену подтверждения и перезапуск. |
| FR-08 | Пользователь может приостановить и возобновить сбор. При паузе скопированный текст не появляется в истории; существующие записи остаются доступны. | Переключить режим и скопировать два текста. |

### 2.3. Хранение

| ID | Требование | Проверка |
| --- | --- | --- |
| FR-09 | История автоматически сохраняется локально и восстанавливается при повторном запуске приложения. | Добавить запись, завершить процесс штатно, запустить снова. |
| FR-10 | История ограничена 500 записями: при добавлении 501-й удаляется самая старая. | Добавить 501 различимый фрагмент и проверить порядок и число. |

## 3. Требования к надёжности

| ID | Требование | Проверка |
| --- | --- | --- |
| NFR-01 | После штатного закрытия и повторного запуска сохранённые записи остаются доступными в прежнем порядке. | Проверить на Windows и macOS. |
| NFR-02 | При ошибке чтения хранилища приложение сообщает о проблеме, не перезаписывает повреждённый файл автоматически и позволяет начать с пустой истории только после явного действия пользователя. | Подменить хранилище некорректным файлом. |
| NFR-03 | При отсутствии доступа к системному буферу приложение сообщает о недоступности сбора и продолжает показывать сохранённую историю. | Смоделировать отказ доступа на поддерживаемой ОС. |

## 4. Требования к интерфейсу

| ID | Требование | Проверка |
| --- | --- | --- |
| UI-01 | Интерфейс на русском языке показывает список, поиск, полный текст выбранной записи, дату/время и действия «Скопировать», «Удалить», «Очистить историю», «Пауза/Возобновить». | Осмотреть окно и выполнить каждое действие. |
| UI-02 | Состояния «История пуста», «Ничего не найдено», «Сбор приостановлен» и ошибка доступа различимы текстом, а не только цветом. | Воспроизвести каждое состояние. |
| UI-03 | Основные действия доступны с клавиатуры, фокус видим; перед необратимой очисткой всей истории показывается диалог подтверждения. | Пройти сценарий без мыши. |

## 5. Требования к техническому обеспечению и данным

| ID | Требование | Проверка |
| --- | --- | --- |
| TEC-01 | Настольное приложение поддерживает Windows 10/11 и macOS 12 или новее; доступно не менее 2 ГБ оперативной памяти и 100 МБ свободного места. | Запуск и сценарии приёмки на обеих платформах. |
| TEC-02 | История хранится локально в профиле текущего пользователя. Приложение не отправляет содержимое буфера по сети и не ведёт журнал с полными текстами записей. | Проверить расположение файлов и сетевую активность. |
| TEC-03 | При первом запуске интерфейс сообщает, что в истории могут оказаться пароли и другие чувствительные данные, и объясняет паузу и очистку. | Проверить первый запуск и действия. |

**Примечание о безопасности:** локальное хранение не означает шифрование. Если требуется защита содержимого от другого пользователя с доступом к файлам устройства, это отдельное требование следующей версии.
